# Changelog

All notable changes to `egui-map` are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/) (pre-1.0:
any minor bump may include breaking changes, called out below as such).

## [0.9.1] - 2026-09-23

### Added

- `Map::remove_marker`, the counterpart of `Map::update_marker`: removes a
  marker and returns the node it pointed to (`None` if there was none).

### Fixed

- Custom `NodeTemplate` hooks and the built-in marker effects paint through
  the `Ui` they get (`ui.painter()`), which wasn't clipped to the map's
  drawable area: nodes near the edge were drawn over the widget's frame and
  onto whatever was next to it. That `Ui` is now clipped like the map's own
  painter.

## [0.9.0] - 2026-09-20

Breaking release: `ThemeColors` gains a required field, `Style` loses one field
and gains another mandatory one, and `MapSettings` drops its two-slot style vector.

### Added

- `ThemeColors::marker`, a new color role for a *lasting* "this is marked"
  indicator: a node's persistent state (`halo`/`blink`/`orbit`, started
  through `Map::node`) and a plain marker set with `Map::update_marker`.
  Deliberately distinct from `selected` (which node the pointer is nearest,
  right now) and `alert` (a one-off event playing out). All 15 built-in
  themes define it.
- `ThemeColors::background`, so the map canvas's background now resolves
  from the active `MapTheme` for the current `ColorMode`, exactly like every
  other role, instead of always following the host application's own
  `egui::Visuals`.
- New built-in theme `Theme::SystemDefault` (renamed from the working name
  `EguiDefault`), now the enum's `#[default]` variant, first in the list.
  Its colors are sourced directly from `egui::Visuals::dark()`/`light()`
  (`hyperlink_color`, `noninteractive.bg_stroke`, `warn_fg_color`,
  `error_fg_color`, `strong_text_color()`), with `selected` boosted in Dark
  mode to stay at least as saturated as `marker`.
- `RegionLabel` and the `LabelTemplate` trait: a new kind of label anchored
  to an area of the map rather than to a single node. Unlike node names and
  `MapLabel`s, a region label's font size scales *with* zoom instead of
  staying screen-constant, and it is always painted first (a background
  layer, behind everything else). Glyph layout is cached per
  (text, rounded size, font family), so a theme or alpha change never
  invalidates the cache. New API: `Map::add_region_labels`,
  `Map::set_label_template`, `Style::region_label_font` (a mandatory
  `FontId` — both family and size are read directly by the built-in
  renderer).
- Viewport culling for region labels: a label whose projected center falls
  well outside the visible rect (plus a margin scaled to the current font
  size) is skipped before any layout or paint work happens, instead of
  being laid out and painted every frame regardless of visibility.
- `theme_gallery/<Theme>.svg`: one self-contained SVG preview per theme
  (light and dark side by side), generated by a new standalone Rust tool,
  `scripts/generate_theme_gallery`, which replaces the previous Python
  script and the single combined `theme_gallery.png`. `THEMES.md` now
  embeds each theme's own SVG inline and lists a `Background` column
  alongside the other five color roles.

### Changed

- All 15 built-in themes were redesigned for visual cohesion across the
  catalog: `node`/`text`/`background` (and, for the 14 non-default themes,
  `alert`/`selected`/`segment` too) were reworked, and every theme now
  defines its own `marker` (same hue as `alert`, half its saturation) and
  `background`.
- Flat markers (`Map::update_marker`) now resolve to `ThemeColors::marker`
  instead of `ThemeColors::alert` — a visible change for anyone using flat
  markers without installing a custom `MapTheme`.
- Node background chips (`NodeContext::background_color`) now use
  `extreme_bg_color` from the host `egui::Visuals` instead of
  `faint_bg_color`, for better contrast against the map canvas.
- Per-node theme and background-color lookups are now resolved once per
  paint batch instead of once per role per node, cutting redundant calls
  to `Theme::colors()` and `egui::Context::theme()` in busy scenes.
- `MapSettings.styles: Vec<Style>` collapsed to a single
  `MapSettings.style: Style` (**breaking**) — the two light/dark slots held
  identical data once `background_color` moved out of `Style` (see
  Removed). `Map`'s internal `current_index: usize` became `dark_mode:
  bool`, and the now-trivial `Map::current_style()` helper was removed.

### Fixed

- `ArticCyan` and `SolarAmber` had their entire Light/Dark color blocks
  transposed, making text illegible against light backgrounds. Added a
  permanent WCAG AA (4.5:1) contrast regression test covering all 30
  (theme, mode) combinations.
- The `THEMES.md`/SVG generator's `theme.rs` parser normalizes `\r\n` line
  endings before matching, fixing a bug where a stray `#[default]` token
  leaked into a theme's tagline on CRLF (Windows) checkouts.
- Stale documentation referencing colors and fields removed in earlier
  releases (a `Style::alert_color` that hasn't existed since 0.6.0, a
  `NodeStyle::fill_color` from a much older version of the crate) rewritten
  to describe current behavior.

### Removed

- `Style::background_color` (**breaking**) — the canvas background is now
  `ThemeColors::background` on the active `MapTheme`; nothing ever actually
  painted a background from this field (the canvas never had one of its
  own), so removing it drops dead state rather than changing rendering.
- `MapSettings::region_label_size` (**breaking**) — superseded by the now
  mandatory `Style::region_label_font.size`.

## [0.8.0] - 2026-09-15

### Added

- Every context struct handed to a `NodeTemplate`/`SegmentTemplate` hook
  (`NodeContext`, `SelectionContext`, `NotificationContext`,
  `MarkerContext`, `SegmentContext`, `SegmentNotificationContext`,
  `SegmentStateContext`) now also carries the full active palette as
  `theme: ThemeColors`, alongside the already-resolved `color` for that
  specific element.

### Changed

- Node names and free-floating `MapLabel`s now paint with `ThemeColors::text`
  from the active `MapTheme`, instead of the host application's own
  `egui::Visuals` text color.
- Flat markers (`Map::update_marker`) fall back to `ThemeColors::alert`
  instead of a color hardcoded to dark/light mode.
- Doc comments on `Notification`, `NodeState`, `SegmentNotification` and
  `SegmentState` corrected to point at `ThemeColors::alert` (the real
  fallback) instead of a `Style::alert_color` that stopped existing back in
  0.6.0.
- Doc comments clarified that `Style::background_color` and
  `NodeContext::background_color` deliberately keep following the host
  application's own visuals rather than the active `MapTheme` — confirmed
  as intentional, not an oversight.

### Removed

- `NodeContext::text_color` (**breaking**) — redundant now that node names
  correctly resolve to `ctx.theme.text`.

## [0.7.0] - 2026-09-14

### Added

- Context structs gain a resolved `color: Color32` field — the element's
  own override if it has one, otherwise the matching role already pulled
  from the active theme — on `NodeContext`, `SelectionContext`,
  `NotificationContext`, `MarkerContext`, `SegmentContext`,
  `SegmentNotificationContext` and `SegmentStateContext`, so a custom
  `NodeTemplate`/`SegmentTemplate` no longer has to repeat the theme
  fallback logic itself.
- New integration tests: `tests/label_projection.rs`,
  `tests/node_context_colors.rs`, `tests/segment_template_context.rs`.

## [0.6.1] - 2026-08-26

### Fixed

- Republished after `0.6.0` was yanked from crates.io — the build actually
  published there came from an intermediate local state (not this tagged
  commit) whose `NodeContext` had a `name: String` field breaking its
  `#[derive(Copy)]`, plus an unused `SelectionContext` field. No source
  change was needed against this tag's own tree, only the version bump.

### Changed

- Internal cleanup, no behavior change: replaced `Vec::new()` +
  repeated `.push()` with `vec![...]` literals across the test suite
  (clippy's `vec_init_then_push`), and tightened a couple of rustdoc links.

## [0.6.0] - 2026-08-25

### Changed

- **Breaking:** `NodeTemplate::node_ui`/`selection_ui` (and the equivalent
  hooks on the other template traits) now take a single context struct
  (`NodeContext`, `SelectionContext`, ...) instead of a list of individual
  parameters (position, zoom, point, ...).
- Colors no longer live on `Style` directly — every role is resolved from
  the active `MapTheme` instead.
- The bundled `DiamondNodes`/`SvgNodes` example templates updated to the
  new context-struct API.

### Added

- A catalog of built-in themes, with a preview screenshot, documented in
  the README.

## [0.5.1] - 2026-08-24

### Added

- `THEMES.md`, documenting every built-in theme's palette, plus a generated
  `theme_gallery.png` preview image. Documentation-only release, no source
  changes.

## [0.5.0] - 2026-08-24

### Added

- The theme system: `src/map/theme.rs` (new file, ~550 lines) — the
  `MapTheme` trait, `ThemeColors`, and the first set of built-in `Theme`
  variants, installable with `Map::set_theme`.
- Segment animations and effects, mirroring the per-node animation API
  added in 0.4.0 (`examples/animations.rs`, `tests/segment_animations.rs`).
- `examples/node_template_animations.rs` and `tests/node_template_kind.rs`.

### Changed

- Substantial rework of `src/map.rs`, `src/map/objects.rs` and
  `src/map/animation.rs` to route colors through the new theme system
  instead of ad hoc fields.

## [0.4.0] - 2026-08-24

### Added

- Per-node persistent fill color: `MapPoint.color: Option<Color32>`, used
  by the default circle when no `NodeTemplate` is installed.
- Per-node animation API: `Map::node(id) -> Option<NodeHandle>`, with
  chainable `.color()`, `.pulse()`, `.ripple()`, `.countdown()`,
  `.scale_in()`, `.crosshair()`, `.halo()`, `.blink()`, `.orbit()` and
  `.clear()` — new `NodeAnimation`/`SteadyAnimation` types in
  `map::objects`.
- Zoom-aware text sizing, so node names and labels keep a fixed on-screen
  size regardless of zoom (`MapSettings.node_text_size`/`label_text_size`).
- Profiling support via `tracing`/`tracy`: new `examples/tracy_profile.rs`
  and a README section.
- New test files: `tests/debug_overlay.rs`, `tests/node_animations.rs`,
  `tests/text_scaling.rs`.

### Changed

- The debug overlay is now collapsible.

## [0.3.1] - 2026-08-13

### Changed

- Replaced the `puffin` profiling feature with a `tracing`-based one
  (renamed `tracy`, then `profile`, in later releases) — removed and
  reintroduced under the new approach within the same release.

## [0.3.0] - 2026-08-12

### Added

- A function to add segments through an `RTree`, superseding the switch to
  a `KdTree`-based approach made in 0.2.1.

### Changed

- **Breaking:** updated `egui`/`eframe` to 0.36.1.
- **Breaking:** `MapPoint`/`MapSegment` coordinate fields switched from
  separate scalar fields to fixed-size arrays.

## [0.2.3] - 2026-07-23

### Changed

- **Breaking:** point storage in the examples and integration tests
  switched from `HashMap` to `Vec`.

## [0.2.2] - 2026-07-23

### Fixed

- The widget showed a light color scheme instead of following the host
  application's active system scheme (dark/light).

## [0.2.1] - 2026-07-23

### Changed

- **Breaking:** `Map::add_lines` now expects an `RTree` instead of a
  `KdTree`.

## [0.2.0] - 2026-07-22

### Changed

- **Breaking:** `MapLine` removed, replaced by `MapSegment`. Lines between
  two points that are both outside the viewport are now still painted
  (previously culled incorrectly), and every segment is indexed once at
  load time instead of being rebuilt per frame.
- Added an optional `debug_overlay` feature for inspecting the widget's
  internal state.

### Fixed

- Typos in `VisibilitySetting`, a duplicated label paint, and a `HashMap`
  cloning bug in `add_points`.

## [0.1.0] - 2026-07-21

### Added

- `CONTRIBUTING.md`.
- Runnable examples: `examples/basic.rs`, `examples/custom_template.rs`,
  `examples/svg_template.rs`, plus sample SVGs used by them.

### Fixed

- Typos in `VisibilitySetting`; a duplicated label paint; a `HashMap`
  cloning bug in `add_points`; assorted other minor breaking changes.

## [0.0.20] - 2026-07-19

### Added

- Full rustdoc documentation across the public API, including a
  crate-level overview and quick-start example in `src/lib.rs`.

### Removed

- Dependabot configuration (`.github/dependabot.yml`).

## [0.0.19] - 2026-07-18

### Fixed

- `RawPoint`'s `Mul`/`Div` (and `*Assign`) operators were not applying the
  correct scaling factor for several numeric conversions.

### Added

- Extensive unit test coverage for `RawPoint`/`RawLine` arithmetic and
  conversions (`Mul`, `Div`, `Add`, `Sub`, and `From`/`Into` for various
  integer and float array types).

## [v0.0.18] - 2026-07-18

### Changed

- Dependency updates (including `egui`); a handful of internal `usize` →
  `isize` conversions; minor clippy fixes; Rust toolchain bump.

## [0.0.15] - 2025-09-29

### Added

- Migrated the internal coordinate representation to `RawPoint`/`SdePoint`,
  a three-coordinate system with a projection step down to `Pos2`
  (replacing the earlier flat 2D representation).
- `Map::set_pos_from_nodeid`; `Clone` for `Map`; `Map::update_marker` for
  tracking markers over time; a dedicated marker-setting method.
- The first template-driven custom rendering hooks for selection and
  notifications.
- Widget sizing: `min_size`/`max_size`, and explicit width/height setters.

### Changed

- **Breaking:** relicensed from a dual Apache-2.0/MIT license to MIT only.

### Fixed

- Nodes did not appear on the map until the first interaction with the
  widget.

## [0.0.13] - 2024-03-28

### Added

- `ContextMenuManager` trait, letting a consumer define and handle their
  own right-click context menu — replaces an earlier, more complex
  `ContextManager` struct.
- `NodeTemplate` trait — the first version of the custom node rendering
  hook.
- A two-point-array constructor for `MapLine`.
- More `puffin` markers for debugging.

### Changed

- **Breaking:** removed the `dimension` field from `MapPoint`, ahead of the
  three-coordinate projection system landing in 0.0.15.
- **Breaking:** `MapPoint`'s `id` and `name` became private.
- Stopped auto-inverting coordinates internally — not the widget's
  responsibility to fix caller data.
- Updated to egui 0.27.

## [v0.0.12] - 2024-03-05

Earliest tagged release in this repository's history — there is no prior
tag to diff against, so no entry is derived here.
